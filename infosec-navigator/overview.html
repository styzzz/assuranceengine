Information security module

Know which security controls work, and what proves it.

The InfoSec Navigator turns information security objectives into testable controls. Each one names the read-only evidence an assessor needs, the test steps, and the conditions under which the assessor must abstain instead of guessing.

Why it exists

Security reports say a control exists. They rarely show it works today.

Most information security reviews sample a few items at one point in time and record a yes or no. The navigator asks a narrower question and requires proof for each answer.

01

Controls drift

A control that passed in March can fail in June. Without a freshness window and a repeatable test, the result goes stale unnoticed.

02

Frameworks overlap

ISO 27001, NIST CSF and SOC 2 ask for much of the same thing in different words. Mapping one control to all three avoids testing it three times.

03

Guesses look like findings

When evidence is missing, a summary often reads as a pass. The navigator makes the missing evidence the result: insufficient evidence, with the reason written down.

How it works

Four steps from objective to a reviewed result

The same steps apply to every control in the catalogue.

STEP 01

Choose the objective

Pick a control from one of seven architecture components, such as Cloud Security or Application Security.

STEP 02

Collect read-only evidence

Each evidence source is read-only. The excerpt is hashed when it is collected so any later change is detectable.

STEP 03

Run the test steps

The assessor follows the written test steps and compares the evidence with the pass criteria.

STEP 04

Decide, then review

The result is one of six states. A person approves it. Missing evidence is recorded as insufficient evidence.
